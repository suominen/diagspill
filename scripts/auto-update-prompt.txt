DiagSpill (CVE-2026-74469) is a heap overflow in the Linux kernel's SCTP
sock_diag reporting. sctp_assoc_add_peer() counts an association's peer
transports in a 16-bit transport_count; the 65,536th unique peer wraps it
to zero, and sctp_diag then reserves a zero-length INET_DIAG_PEERS payload
but copies every transport's sockaddr_storage anyway — about 8 MiB written
past the skb tail. An unprivileged local user with the sctp and sctp_diag
modules available can build the association and issue the diag dump
itself; no user namespace or capability is needed.
The canonical fix is bd0e9289e264 (sctp: prevent peer transport count
overflow), first released in v7.2-rc6. The bug was introduced by
8f840e47f190 (sctp: add the sctp_diag.c file) in v4.7, so the reachable
window is 4.7 through 7.1 (and 7.2 before -rc6) — every maintained kernel
line and every tracked distro kernel is in-window; there are no
not-affected rows.
DiagSpill was disclosed together with three other bugs by the same
discoverer — DirtyAH6 (CVE-2026-80844), TUNderflow (CVE-2026-81000), and
PPPoEject (CVE-2026-68121) — each tracked separately at
https://kimmo.cloud/{dirtyah6,tunderflow,pppoeject}/. They have their own
fixes and first-fixed releases; do not mix their status into this tracker.

Working-tree hygiene: stream a fetch through a pipe — `curl -fsSL <url> |
grep …` — when one pass over the data is enough. If you genuinely need a
scratch file, save it in the worktree under a `.scratch-` prefix (e.g.
`.scratch-advisories.json`), work on it there, and `rm` it before you
commit — never `git add` a scratch file. Write it with `curl -o
.scratch-…` or `… | tee .scratch-… > /dev/null`: a shell redirection into
a file (`> .scratch-…`) is refused by Claude Code even inside the
worktree, and retrying it in another spelling is wasted effort
(`/dev/null` is the one redirection target that passes). Read it back
with an allowlisted reader (`zcat .scratch-x.gz | grep …`,
`jq … .scratch-x.json`).
Don't use /tmp: Bash file reads are confined to the worktree, so a file
there can be written but not read back. The wrapper's `git clean -fd`
sweeps forgotten scratch on the next run, but the only thing you should
leave behind is the edited tracker (and its commit).

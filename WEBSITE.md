# Website plan — `https://kimmo.cloud/diagspill/`

Publish the DiagSpill tracker as a single-page static site, generated by
**Hugo** locally and rsync'd to a personal nginx server (`haig`). The build
infrastructure mirrors the sibling trackers; only the content and a few
config strings differ.

## Architecture

- **Source repo:** `github.com/suominen/diagspill` (this repo).
- **Generator:** Hugo ≥ 0.146.0 (standard edition). Run locally; nothing
  built in CI.
- **Source layout:** Hugo project under `site/`; the tracker is a single
  page at `site/content/_index.md`.
- **Theme:** PaperMod, integrated as a Hugo Module (no submodule).
- **Dev environment:** Nix flake (`flake.nix`) provides everything the
  build, banner, publish, and lookup recipes call (Claude Code itself
  excepted). Auto-activates via `.envrc` with direnv.
- **Build:** `make build` → `hugo --minify --gc --cleanDestinationDir`.
- **Publish:** `make dist` → `rsync -avz --delete site/public/` →
  `haig:/diagspill/`.
- **Web server:** existing nginx vhost on `kimmo.cloud` serves
  `htdocs/diagspill/` at the URL path `/diagspill/`.

## Naming — nickname slug (CVE assigned)

The bug carries a name (**DiagSpill**) *and* a CVE (**CVE-2026-74469**)
from the outset — the name is the one the discoverer's write-up and PoC
use. Following the sibling precedent — which runs both ways (ghostlock,
januscape, pintheft, cifswitch, and sctphantom kept nicknames; Dirty Frag
was renamed to `/CVE-2026-43284/`) — the site uses the **nickname** as its
slug everywhere, with the CVE carried in the tracker body, Summary, and
title:

- repo: `~/src/diagspill`, `github.com/suominen/diagspill`
- Go module path: `github.com/suominen/diagspill/site`
- URL: `https://kimmo.cloud/diagspill/`
- systemd units: `diagspill-tracker-update.{service,timer}`

No redirect is needed; the slug never moves.

## Companion trackers

DiagSpill was disclosed together with three other local-root bugs by the
same discoverer (the oss-security "quartet" post of 2026-09-18), each with
its own tracker under the same nickname-slug scheme:

- **DirtyAH6** (CVE-2026-80844) — `https://kimmo.cloud/dirtyah6/`
- **TUNderflow** (CVE-2026-81000) — `https://kimmo.cloud/tunderflow/`
- **PPPoEject** (CVE-2026-68121) — `https://kimmo.cloud/pppoeject/`

They are different bugs in different subsystems (IPsec AH6, TUN, PPPoE)
with their own fixes and their own first-fixed releases, so each tracker
keeps its own verdict axis. The four cross-link through a *Related* row in
each Summary table, a closing sentence in the commit-range prose, and rows
in each References table — the LIFECYCLE.md companion-tracker pattern.
DiagSpill is the odd one out on reachability: the other three need
unprivileged user namespaces (or specific capabilities), DiagSpill needs
neither.

## Tracker content

- One kernel bug, **single verdict axis**: the `bd0e9289e264` fix is the
  only thing that flips a row. There is no userspace reachability gate that
  ships as its own package.
- The reachability gate — the `sctp` and `sctp_diag` modules being
  available — decides *who* can reach an unpatched kernel; it is recorded
  in prose, **not** as columns, and does **not** downgrade a verdict (an
  in-window, unpatched kernel is `:x:` whether or not a given host
  blacklists `sctp`).
- **No "Not affected" rows.** The flaw was introduced by `8f840e47f190`
  in **v4.7** (2016) — the `sctp_diag` module itself — so every maintained
  upstream line and every tracked distro kernel (EL8's 4.18 included) is
  in-window. A row is `:x:` until its kernel carries the backport.
- **Patch status** uses a single combined table for upstream and distros
  (`Distribution | Release | Current kernel | First fixed | Fixed since |
  Status`): the upstream kernel is the first `Linux kernel` group, opt-in
  kernels get their own rows, and per-distro `###` headings appear only
  where there is an audience-relevant note. In the browser the
  Distribution column renders as full-width group heading rows, and the
  column header and group headings are sticky.
- Seed every row from sourced facts — no unconfirmed "fixed" claims.
- Social banner: `site/assets/diagspill-tracker.svg` → `.png` via
  `make banner`.

## Decisions

- **Hosting:** own nginx on `haig`, not GitHub Pages.
- **URL:** `https://kimmo.cloud/diagspill/` (nickname slug; see "Naming").
- **Canonical source:** `site/content/_index.md`.
- **No not-affected rows:** the introducing commit is the `sctp_diag`
  module's birth in v4.7, older than every tracked kernel, so no row can be
  out of window on age grounds.
- **Automated maintenance:** a user-level systemd timer runs
  `scripts/auto-update`, which merges `origin/main` into a long-lived
  `auto-update` branch in a separate worktree and hands off to headless
  Claude. The agent commits onto `auto-update` only. Merges to `main` are
  manual.

## Risks & gotchas

- **Subpath baseURL** must keep the trailing slash and path component.
- **`.cleanDestinationDir`** wipes `site/public/` before each build.
- **rsync `--delete`** removes server-side files not in the build output.
- **Anchor drift:** Hugo/Goldmark's slugger differs from GitHub's; pin
  brittle headings with `### Heading {#stable-id}` if needed.
- **Sibling links:** the three companion-tracker URLs 404 until those
  trackers go live; they are being seeded in parallel.
